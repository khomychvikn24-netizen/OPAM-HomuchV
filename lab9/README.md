# Лабораторна робота №9. Реалізація та порівняння алгоритмів сортування

Виконала: Варвара, КН-3/1. Мета: реалізувати узагальнені сортування, перевірити їхню правильність, складність і стабільність експериментально.

## Запуск і структура

.NET SDK 10: `dotnet run -c Release --project lab9/Lab09.csproj` із кореня репозиторію.
Повний запуск виконує всі заміри, включно з повільною бульбашкою на 100000 елементів, тому може тривати кілька хвилин.

Sorts.cs — узагальнені алгоритми; Verification.cs — IsSorted та IsPermutationOf; Measurements.cs — заміри; Program.cs — генерація, досліди, трасування та перевірки.

## Варіант і методика

N=29, K=3: числа [0;60], Random(29), Bubble з прапорцем, ітеративне Merge знизу вгору, експеримент із двома ключами Student (Group, потім Score). Додатковий варіант c=4 є експериментом над Merge, а не третім окремим числовим алгоритмом: у відповідних колонках виміряно два стабільні проходи для Student[]. Числові й студентські колонки мають різні типи даних і безпосередньо не доводять перевагу одного компаратора над іншим.

Усі порівняння виконуються через Func<T,T,int>. Запис у будь-який масив елементів, включно з буфером Merge, вважається переставлянням; запис у локальну змінну не рахується. Bubble обмінює пару двома записами. Буфер Merge виділяється один раз на виклик, ділянки мають ширину 1,2,4,…, обидва хвости копіюються.

BubbleSort/MergeSort мають навчальну сигнатуру з out int. Для великих часових дослідів ядра Bubble/Merge використовують out long: вже на 100000 випадкових елементів число записів може перевищити int.MaxValue. Обгортки виконують checked-перетворення, а не допускають тихе переповнення. Таблиці лічильників до 10000 елементів використовують int без переповнення.

Чотири входи: випадковий; відсортований; зворотний (власні обміни); майже відсортований — після 3 випадкових обмінів із Random(29). Для Student типи входу будуються за складеним ключем Group/Score. Після кожного досліджуваного сортування, включно з кожним часовим прогоном, викликаються обидві перевірки. IsPermutationOf рахує частоти значень, для Student зберігається тотожність об'єктів.

Bubble на відсортованому вході має рівно n−1 порівнянь і 0 записів: прапорець спрацьовує одразу. На випадковому й зворотному входах число порівнянь близьке до n(n−1)/2; повтори й прапорець іноді скорочують останні проходи. Майже відсортований масив має менше обмінів, але елемент, що повинен рухатися ліворуч, проходить лише одну позицію за прохід, тому порівнянь усе ще багато.

Merge проходить однакові рівні незалежно від входу, тому число записів однакове: 2n·ceil(log₂n). Порівняння відрізняються, бо після вичерпання однієї половини її хвіст уже не порівнюється. Два проходи Merge удвічі збільшують кількість записів; проміжне сортування за Score не обов'язково зберігає порядок за Group.

## Два ключі та стабільність

Для порядку «група, потім бал» складений компаратор спочатку порівнює Group, а при рівності — Score. Два стабільні проходи виконуються у зворотній пріоритетності: спочатку Score, потім Group. Результати збіглися, включно з порядком тих самих об'єктів; нестабільний другий прохід міг би зруйнувати порядок за балом. Сортувати спочатку Group, потім Score було б неправильно для заданої головної ознаки.

Очікування зафіксовані в коді до викликів: Bubble і Merge стабільні, Array.Sort не гарантує стабільності, OrderBy стабільний. Використано 100 Student із прізвищами, заздалегідь упорядкованими Ordinal, та повторюваними балами.

| Алгоритм | Очікувано | Фактично | Перший контрприклад |
|---|---|---|---|
| Bubble | Стабільний | True | Немає |
| Merge | Стабільний | True | Немає |
| Array.Sort | Стабільність не гарантована | False | Прізвище0000049 перед Прізвище0000036, бал 3 |
| OrderBy | Стабільний | True | Немає |

OrderBy використано **лише** у прямо запитаному еталонному експерименті стабільності. У власних алгоритмах LINQ немає. Bubble не міняє рівних сусідів; Merge при рівності бере лівий елемент — це зберігає початковий порядок.

## Відповіді завдання 6

**Відношення проти 376.** Для випадкового n=10000 маємо 49983372 / 123150 ≈ 405,87, що більше за 376. Число 376 є лекційною оцінкою, а власні алгоритми мають інші константи: Bubble з прапорцем, Merge з неповними хвостами, лише 61 різне значення. На відсортованому вході це відношення зовсім інше — через ранню зупинку Bubble.

**Чому Array.Sort може бути швидшим?** Для цілих чисел стандартне сортування працює на місці, а Merge виділяє буфер і на кожному рівні двічі записує всі елементи. Крім того, стандартна реалізація використовує гібридну стратегію з окремою обробкою коротких ділянок, тоді як наш Merge завжди проходить усі рівні та викликає переданий Func. На n=10000 у цьому запуску власний Merge навіть швидший; отже перевага Array.Sort не є законом для кожного окремого заміру.

**100000 записів, ключ 0–300, стабільність обов'язкова.** Виберу стабільне сортування підрахунком: порахувати 301 частоту, обчислити початкові позиції груп і пройти початкові записи зліва направо, записуючи у вихідний масив на наступну позицію ключа. Час O(n+301), додаткова пам'ять O(n+301), відносний порядок записів із однаковим ключем збережено. Просте відновлення чисел із частот не підійшло б для повних записів Student.
