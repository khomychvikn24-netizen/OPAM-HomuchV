# Лабораторна робота №3. Рекурсивні алгоритми

Виконала: Варвара, КН-3/1. Мова: C#.

## Мета роботи

Реалізувати рекурсивний обхід ієрархії каталогів, розбиття масиву навпіл і перебір із поверненням; дослідити стек викликів та порівняти рекурсію з циклом.

## Варіант і запуск

В — третя літера української абетки, тому K = 3. N % 3 = 2, N % 4 = 1, N % 5 = 4.
Завдання 1: максимальна глибина папок. Завдання 2: чи всі елементи однакові. Завдання 3: розмін S = K % 10 + 8 = 11 грн монетами 1, 2 та 5.

Потрібен .NET SDK 10. Із кореня репозиторію:

```console
dotnet run --project lab3/Lab03.csproj
```

Після запуску ввести шлях до папки з клавіатури, без зовнішніх лапок. Для автоматичних перевірок:

```console
dotnet run --project lab3/Lab03.csproj -- --test
```

## Хід роботи та методи

| Завдання | Метод | Принцип |
|---|---|---|
| 1 | FolderDepth | Рекурсивно обробляє безпосередні підпапки та повертає найбільшу їхню глибину плюс один |
| 2 | Solve(int[] a, int lo, int hi) | Викликає рекурсивне перевантаження, що перевіряє обидві половини й рівність їхніх перших елементів |
| 3 | Change | Перебирає кількість монет кожного номіналу, повертає число варіантів та скасовує вибір після рекурсивного виклику |
| 4 | Solve з depth, maxDepth і trace | Друкує вхід і вихід із двома пробілами відступу на рівень та повертає максимальну глибину через out |
| 5 | SolveIterative | Порівнює кожен елемент із першим звичайним циклом |

Допоміжні PrintArray, RunTests та Check відповідають за виведення та перевірки. Глобальних накопичувачів немає; LINQ і готові рекурсивні обходи не використовуються.

### Базові випадки

- **FolderDepth:** у доступній папці без підпапок цикл не виконується, тому повертається 0.
- **Solve:** діапазон з одним елементом або порожній діапазон (lo >= hi) повертає true.
- **Change:** від'ємний залишок повертає 0; після розгляду всіх номіналів повертається 1 лише для нульового залишку, інакше 0.

Коренева папка має глибину 0, її безпосередня підпапка — 1. Недоступні папки пропускаються з повідомленням: UnauthorizedAccessException перехоплюється, повертається службове значення -1. Якщо пропущено частину дерева, результат стосується лише доступної частини. IOException також перехоплюється, наприклад якщо папку видалено під час обходу. Посилання на папки та інші reparse points пропускаються, щоб уникнути циклічних переходів.

## Результати виконання

Масив згенеровано через new Random(29), Next(-20, 21):

```text
[15, -7, -19, 10, -8, 16, 16, 20, 3, 19, 6, -16, 3, 2, -9, -15]
```

Рекурсивна відповідь — False. Циклічна відповідь — False. Результати збіглися.
Обидві половини обчислюються завжди: скорочене обчислення логічного виразу не перериває рекурсивний обхід.
Глибина від кореня з depth = 0 становить 4 переходи, тобто 5 одночасних рівнів рекурсивного перевантаження Solve; log₂16 = 4. Обгортка Solve з трьома параметрами, коли її викликають, є додатковим службовим викликом і до глибини поділу не входить.

Приклад обходу папки lab3 після збирання дав глибину 4; конкретний результат залежить від фактичного дерева каталогів.

### Усі способи розміну

Кожен рядок показує кількість монет номіналу 1, 2 та 5 грн відповідно:

```text
1 грн: 0; 2 грн: 3; 5 грн: 1
1 грн: 1; 2 грн: 0; 5 грн: 2
1 грн: 1; 2 грн: 5; 5 грн: 0
1 грн: 2; 2 грн: 2; 5 грн: 1
1 грн: 3; 2 грн: 4; 5 грн: 0
1 грн: 4; 2 грн: 1; 5 грн: 1
1 грн: 5; 2 грн: 3; 5 грн: 0
1 грн: 6; 2 грн: 0; 5 грн: 1
1 грн: 7; 2 грн: 2; 5 грн: 0
1 грн: 9; 2 грн: 1; 5 грн: 0
1 грн: 11; 2 грн: 0; 5 грн: 0
Кількість способів: 11
```

Порядок монет не створює нового способу. Повнота перевіряється також незалежним підрахунком: без монет по 5 грн є 6 способів, з однією — 4, з двома — 1; разом 11. Усі кількості невід'ємні, а сума номіналів у кожному рядку дорівнює 11.

## Трасування для [7, 7, 7, 4]

Фактичний вивід програми:

```text
enter Solve(0..3)
  enter Solve(0..1)
    enter Solve(0..0)
    exit  Solve(0..0) -> True
    enter Solve(1..1)
    exit  Solve(1..1) -> True
  exit  Solve(0..1) -> True
  enter Solve(2..3)
    enter Solve(2..2)
    exit  Solve(2..2) -> True
    enter Solve(3..3)
    exit  Solve(3..3) -> True
  exit  Solve(2..3) -> False
exit  Solve(0..3) -> False
```

Для вкладених викликів exit з'являються у зворотному порядку до enter, оскільки стек працює за принципом «останнім увійшов — першим вийшов». Батьківський виклик очікує результати дочірніх і завершується тільки після їх повернення; сусідні гілки виконуються послідовно.

## Перевірка крайових випадків

| Вхід | Завдання | Очікувано | Отримано |
|---|---|---|---|
| Порожня папка | 1 | Глибина 0 | 0, OK |
| Папка без доступу | 1 | Повідомлення, пропуск без падіння | Обробник повернув -1 і вивів повідомлення, OK; виняток імітовано |
| [5] | 2 | True | True, OK |
| [3,3,3,3] | 2 | True | True, OK |
| Сума -1, монети 1,2,5 | 3 | 0 способів | 0, OK |
| Сума 3, монети 2,5 | 3 | 0 способів | 0, OK |

Для додатної цілої суми з монетою 1 грн неможливого розміну не існує, тому останній тест використовує допоміжний набір номіналів без одиниці. Основний варіант завжди працює з монетами 1, 2, 5.

Тест недоступної папки використовує параметр enumerate та функцію DenyAccess, яка кидає справжній UnauthorizedAccessException; права доступу системних папок не змінювалися. Це перевірка обробника винятку, а не фактичного обмеження ACL у файловій системі.

Додатково перевірено дерево глибиною 2, відсутню папку, порожній масив (True: немає пари різних елементів), різні однорідні половини [3,3,4,4], глибину поділу масиву з 16 елементів, збіг із циклом, скасування вибору й нульову суму (один спосіб — не брати монет). Усі 15 автоматичних перевірок пройшли на .NET SDK 10.0.401; звичайний запуск із введенням папки також завершився успішно.

## Відповіді на питання завдання 5

**Який запис зрозуміліший для перевірки рівності елементів і чому?**

Циклічний запис зрозуміліший: достатньо порівнювати кожен наступний елемент із першим і повернути false при першій відмінності. Він не потребує меж половин, об'єднання результатів та стека рекурсивних викликів. Обидві реалізації мають час O(n) у найгіршому випадку, але цикл використовує O(1) додаткової пам'яті, а рекурсія поділом навпіл — O(log n) пам'яті стека.

**Чому обхід папок не переписати так само просто одним циклом і якої структури бракує?**

Кількість рівнів і підпапок наперед невідома: після переходу до дочірньої папки потрібно пам'ятати ще не відвідані гілки та їхню глибину. Рекурсія зберігає стан викликів у стеку автоматично, а звичайний цикл цього не робить. Для ітеративного обходу в глибину потрібен явний стек пар «шлях, глибина»: діставати папку, оновлювати максимум і класти її підпапки з глибиною на одиницю більшою. Альтернатива для обходу в ширину — черга з тією самою інформацією.

## Висновок

У роботі реалізовано три форми рекурсії: обхід дерева каталогів, поділ масиву навпіл і перебір розміну з поверненням. Для варіанта 29 отримано False при перевірці однаковості елементів та знайдено 11 способів розміну 11 грн. Трасування показало порядок входів і повернень та роботу стека, а порівняння з циклом підтвердило однаковий результат. Крайові випадки перевірено автоматично, відмову доступу оброблено без аварійного завершення.
